# Deployment controls

These files are integration templates, not evidence that the production firewall or provider has been changed. Keep `.env` out of source control.

The administrator Server Info page now shows these effective configuration checks, remediation instructions and manual verification items. It shares its checks with `security:deployment-check`; credential values are not included in the results.

## Required configuration

- Set `TRUSTED_PROXIES` to the **actual immediate ingress IPs/CIDRs**, comma separated. Empty trusts none; never use `*`. Set `TRUSTED_HOSTS` to exact accepted hostnames (canonical host plus any redirect aliases). Forwarded host is deliberately ignored.
- Set `APP_URL` to the canonical HTTPS origin, `APP_DEBUG=false`, `SESSION_SECURE_COOKIE=true`. Production enables canonical redirects; staging uses its own APP_URL and `SITE_INDEXABLE=false`. Signed/token links retain their origin so signatures are not broken.
- Generate a dedicated 32+ character `SMSFLOW_WEBHOOK_SECRET`, different from the outbound API key. Configure SMSFlow to send `Authorization: Bearer <secret>`, or configure its callback URL as `https://<host>/webhooks/smsflow?webhook_secret=<secret>`. Missing/invalid credentials return 401 before payload processing. URL credentials require access-log query suppression at **every** ingress hop. Update any outbound `SMSFLOW_CALLBACK_URL` to the same authenticated URL; no secret is appended to arbitrary destinations automatically.
- Set `SECURITY_ERROR_RECIPIENTS` to an explicit comma-separated restricted recipient list. Alerts contain an error reference, exception class and route name, without exception text, traces or user identity. Production log processors remove exception diagnostics and sensitive context fields; arbitrary legacy free-text messages still require review. Use `LOG_CHANNEL=daily` or `LOG_STACK=daily`, `LOG_LEVEL=info`, `LOG_DAILY_DAYS=14`, and restrict the application OS group.
- `ADMIN_MFA_REQUIRED=true` and `GENERIC_LOGIN=true` are enabled outside automated tests. Existing administrators without an authenticator are redirected to enrolment. Accounts with an enrolled authenticator can sign in directly with TOTP or a backup code, including administrators. Express initiation opens TOTP first, otherwise password, otherwise email verification; GENERIC_LOGIN keeps email-link responses generic. Verification expires after 12 hours, on a new login, or when the secret changes. Administrator MFA cannot be disabled through the account endpoint. Keep unused backup codes offline; lost-authenticator recovery must verify identity through an operator before modifying credentials. Never disable MFA globally to recover one account.
- Use shared Redis/database cache for distributed throttles, MFA replay prevention and snapshots. Keep a durable queue connection; optionally set `ANALYTICS_QUEUE_CONNECTION=redis`. Add the dedicated `analytics` worker using `analytics-worker.conf` (adjust its installation directory). Existing `mail` workers process generic login requests. Failed analytics jobs stop after three attempts; monitor failed jobs and queue age, and set retention using `queue:prune-failed`.
- Run migrations before workers load this release; `event_uuid` makes retried analytics writes idempotent. Schedule Laravel's `schedule:run` every minute. `analytics:snapshot` refreshes all dashboard periods every five minutes. Snapshots expire after `DASHBOARD_SNAPSHOT_SECONDS` (default 300); zero disables serving cached snapshots. Cache payloads use JSON, not serialized PHP objects. Do not use dashboard snapshots as an accounting export.
- Use `PROFILE_REQUESTS=true` temporarily with representative staging data. Request-performance logs contain route names, database counts/times, total time and peak memory, including streamed exports. Compare cold/warm dashboard and report/export workloads at representative row counts. Never enable SQL query logging for this measurement.
- `CSP_REPORT_ONLY=true` reports script violations without blocking existing Alpine/editor code. `/security/csp-reports` accepts bounded, rate-limited reports and logs only directive and broad violation category, aggregated for five minutes. No report document URL, source, sample or referrer is stored. Use `scripts/csp-inventory.py` to locate inline handlers/scripts; move or nonce them before promoting script restrictions to enforcement.

## Release and infrastructure verification

1. Take encrypted database and private-file backups outside `public/`; restore to a disposable environment and record verification time, owner and recovery duration. Existing backup schedules continue unchanged.
2. Restrict origin firewall ingress to the real proxy and management network; strip client-supplied forwarded headers at the public edge. Apply and syntax-check `nginx-location-controls.conf` inside the appropriate TLS vhost, adapting paths for the actual ingress. Do not proxy-cache authenticated HTML, signed media or private downloads. Hashed Vite assets are immutable; `push-sw.js` revalidates.
3. Run `php artisan security:deployment-check` with **cached deployment configuration**. This prints pass/fail labels without secret values; it cannot prove firewall rules or backup restorability. The deploy script invokes this before bringing a release online.
4. Verify TLS certificate chain/renewal, redirect aliases, spoofed Host/X-Forwarded-For rejection, `.env`/Git/log/backup denial, private cache headers and staging noindex from outside the trusted network. Verify the origin is inaccessible directly. Rotate compromised/historical exposed credentials through each provider; do not echo them in terminal logs.
5. Perform a provider test callback and verify missing/wrong secrets return 401; confirm an authentic callback creates exactly the intended inbound record. Check proxy access logs contain no query credential.
6. Restart queue workers after migrations/config rebuild; confirm mail and analytics queues drain and scheduled snapshots refresh. Alert on failed jobs, growing queue age, backup failures and certificate expiry. Keep logs and failed-job data within the organisation's retention policy; historical copies need their own controlled cleanup.
7. Run `scripts/measure-mobile.sh` against staging (home, store, a published workshop). Lighthouse is a lab measurement; field Core Web Vitals require real-user samples over time. The staging noindex header intentionally lowers its SEO score.

Reference: [Laravel proxy configuration](https://laravel.com/framework/docs/12.x/requests#configuring-trusted-proxies), [SMSFlow callback documentation](https://smsflow.com.au/api), [CSP report-only](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy-Report-Only).
